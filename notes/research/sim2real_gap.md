# sim2real 대비 — 지금 시뮬레이터에 없는 것

> **이번 논문은 시뮬레이션 전용**이고 실기 검증은 Limitations에 명시한다.
> 이 노트는 **나중에 실기로 갈 때 무엇을 먼저 채워야 하는가**의 목록이며,
> 지금 당장 구현할 것이 아니라 **설계 결정이 그 길을 막지 않도록** 남기는 기록이다.

## 1. 근거 — 경쟁 논문의 ablation이 무엇이 중요한지 이미 말해준다

Scaramuzza(arXiv 2606.27603) Table V는 하이브리드 시뮬레이터의 구성요소를 하나씩
제거하고 **zero-shot 실기 성능**을 다시 쟀다. 2.0 m 표적, 착지 오차:

| 제거한 것 | 착지 오차 | 배수 |
|---|---|---|
| **없음 (전체 모델)** | **0.105 m** | 1.0× |
| 공력 (rotor inflow + drag) | 0.342 m | **3.3×** |
| 모터 모델 (1차 지연 → 즉시) | 0.254 m | **2.4×** |
| 저수준 컨트롤러 (실측 → 이상적 기하 제어) | 0.386 m | **3.7×** |
| 유연 케이블 → 강체 봉 | 0.306 m | 2.9× |

**어느 하나만 빠져도 2.4~3.7배 나빠진다.** 즉 sim2real은 "도메인 랜덤화를 넓히면
된다"가 아니라 **"액추에이터 체인을 실측으로 동정(system identification)해야 한다"**
쪽이다. 네 번째(케이블)는 우리에게 해당 없음 — 강체 마운트다.

## 2. 우리가 이미 가진 것

| 항목 | 구현 |
|---|---|
| 기체 바람 항력 | 상대 기류에 대한 2차 항력, 월드→바디 명시 변환 |
| 페이로드 항력 | `is_global=True`로 프레임 정합 완료 |
| 릴리즈 지연 | **플랜트에 실제 구현** + $N(0.22, 0.05)$ 랜덤화 |
| 관측·명령 노이즈 | per-step 백색 + **per-episode 바이어스** (2-타임스케일) |
| 컨트롤러 질량 오차 | 등가 변환(질량 *믿음*을 흔듦, PhysX 런타임 쓰기 없음 — Rule 19) |
| 제어 게인 오차 | `kp_vel`, `k_att_rate` 스케일 랜덤화 |
| 스폰타임 질량·관성 authoring | 런타임 오버라이드 금지 (exp_013 교훈) |

## 3. 없는 것 — 우선순위 순

### ⭐ 3.1 로터 유입류(rotor inflow) / 블레이드 플래핑

**우리 regime에서 가장 크다.** 전진 속도가 붙으면 로터가 받는 유효 받음각이 바뀌어
**추력이 떨어지고 피칭 모멘트가 생긴다.** 정속 패스가 3 m/s에서 던지므로 무시할 수 없고,
Scaramuzza의 ablation에서도 3.3배로 가장 컸다.

현재 `_run_velocity_controller`는 `thrust_mag`를 `f_des·body_z`로만 계산하고
전진 속도에 대한 추력 감소를 모델링하지 않는다.

### ⭐ 3.2 모터 1차 지연 + 명령 전달 지연

현재 rate loop이 **토크를 직접** 만든다 (`torque_b = I * ang_accel_des`).
실제 체인은 `명령 → 전송 지연(τ_d ~10-20 ms) → ESC → 모터 1차 지연(τ_mot ~15-30 ms) → 추력`이다.

⚠️ **릴리즈 판정을 100 Hz(10 ms)로 올려놓았으므로 특히 관련이 있다** —
액추에이터 지연이 20 ms면 판정 해상도의 이득 일부가 지연에 먹힌다.
(다만 릴리즈 *기구* 지연 0.22 s가 지배적이라 실제 영향은 작을 것으로 본다.)

### 3.3 추력–토크 맵과 배터리 전압 강하

`max_thrust`가 스칼라 상수다(`T/W 2.0 × m × g`). 실제로는 모터 회전수와 팩 전압의
함수이고, 전압은 부하에 따라 처진다. **비행 후반에 추력 여유가 줄어든다**는 사실이
빠져 있다.

### ⭐ 3.4 컨트롤러 게인의 실측 캘리브레이션

[[research/isaac_velocity_controller]]에 **`tilt_clamp_deg = 35`가 "임의 초기값"으로
명기**되어 있고 캘리브레이션되지 않았다. `kp_vel_xy = 1.8`, `k_att_rp = 6.5`,
`k_rate = (18, 18, 8)`도 마찬가지다.

**이것이 3.1~3.3보다 먼저다** — 나머지를 다 채워도 게인이 실기와 다르면
동정의 기준점이 없다. Scaramuzza의 "저수준 컨트롤러 이상화" ablation이 3.7배로
가장 나빴던 것도 같은 이야기다.

### 3.5 상태 추정 오차 모델

현재 관측 노이즈는 **참값에 더하는** 방식이다. 실제로는 EKF가 IMU+GPS/모캡을 융합하며
**지연과 드리프트**를 갖는다. 특히 속도 추정 지연은 릴리즈 타이밍에 직접 들어간다.

### 3.6 지면 효과

`termination.min_altitude`를 1.5 m로 낮췄으므로 이제 지면 근처를 난다.
로터 지름의 2배 이내에서 추력이 증가하는 효과가 빠져 있다.

### 3.7 릴리즈 기구의 반작용

릴리즈 지연은 모델링했지만, 서보가 페이로드를 놓는 순간의 **충격·질량 급변**이
기체 자세에 주는 외란은 없다. (질량 급변 자체는 `_ctrl_mass`로 부분 반영.)

## 4. 지금 해야 할 것 — 아무것도 구현하지 않는다

이번 논문은 시뮬레이션 전용이고, 위 항목을 채워도 **실기가 없으면 검증할 수 없다.**
대신 두 가지만 지킨다.

1. **설계가 길을 막지 않게 한다.** 액추에이터 체인을 나중에 끼워 넣을 수 있는 구조를
   유지한다 — 현재 `_run_velocity_controller`는 `(force, torque)`를 한 곳에서 만들므로
   그 앞단에 지연 큐와 모터 모델을 삽입할 수 있다. **이 구조를 깨지 말 것.**
2. **Limitations에 정직하게 쓴다.** *"제어 게인이 실측 캘리브레이션되지 않았고,
   로터 유입류·모터 지연·배터리 모델이 없다. 선행연구의 ablation은 이들 각각이
   zero-shot 실기 오차를 2.4~3.7배 바꾼다고 보고한다."*
   → **약점을 숨기지 않고 크기를 아는 편이 강하다.**

## 5. 실기로 갈 때의 순서

| 순위 | 작업 | 이유 |
|---|---|---|
| 1 | **기체 스텝 응답 실측 → 게인 동정** | 나머지의 기준점 |
| 2 | 모터 1차 지연 + 명령 지연 큐 | 측정이 쉽고 효과가 크다 |
| 3 | 추력–토크 맵 (회전수·전압) | 정적 시험대로 측정 가능 |
| 4 | 로터 유입류 모델 | 전진 비행 시험 필요 |
| 5 | 상태 추정 지연·드리프트 | EKF 로그에서 동정 |
| 6 | 지면 효과 · 릴리즈 반작용 | 나머지가 맞은 뒤 잔차로 |

> Scaramuzza의 핵심 통찰은 **"기체와 페이로드를 하나의 monolithic 시스템으로 모델링할
> 필요가 없다"**는 것이었다 — 6차원 wrench 하나로만 결합하면 **단독 기체를 한 번
> 동정한 결과가 페이로드를 달아도 그대로 전이된다.** 우리 구조도 페이로드가 kinematic
> weld이므로 같은 분리가 가능하다. 실기로 갈 때 이 설계를 따르는 것이 좋다.
