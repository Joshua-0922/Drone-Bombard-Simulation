# L1-SL 파이프라인 개요 — 무엇을, 어떤 입력으로, 어디에 넣어 잔차를 줄이는가

> **한 줄.** 비행 정책(L0)은 그대로 두고, *"공식이 예측한 착탄점과 실제 착탄점의 차이(드리프트)"* 를 관측만 보고
> 맞히는 작은 회귀기(MLP 38→128→128→2)를 따로 학습해, 그 예측값만큼 예측 착탄점을 옮긴다. 망은 평범하고,
> 알맹이는 **정답의 정의**(1단계), **누적 특징**(2단계), **게이트 앞 평활**(5단계) 셋이다.

## 1. 전체 흐름 — 5단계

```
① 수집      동결 L0가 잔차 없이 비행 ─ 0.1 s마다 (관측 26, 정답 드리프트 2) 저장
② 특징      관측 26 + tilt 누적 10 + gi 2 = 38
③ 학습      표준화 → MLP 38→128→128→2 (ELU) → MSE, 에피소드 단위 분할
④ 내보내기  표준화 포함 TorchScript res_gi.pt  (입력 날것 38, 출력 미터 2)
⑤ 주입      매 스텝: 누적 갱신 → 회귀기 → EMA 0.3 → /2 m → ±1 → 행동 채널 5:7
            env: 예측 착탄점 = 공식 CCIP + 2 m × 채널 → (a) 게이트·첫 교차(언제 놓나) (b) L0의 조준 오차 관측(조향)
```

### ① 데이터 수집 — `play.py --dump_sl`

| 항목 | 값 |
|---|---|
| 비행 | 동결 L0 seed 1, `--no_residual`(결정론), DR 1.5, 사거리 18–22 m, 256 envs |
| 수집 시드 / 규모 | 1000·2000 / 3,000 에피소드 ≈ 3,501 슬롯-에피소드, 약 18만 프레임 |
| 저장 항목 | 관측 26 · **정답 드리프트 2(미터)** · 참 바람 · 경과 스텝 · 부착/탐지 플래그 |
| 정답 정의 | `oracle_impact_residual(wind_only=True)`: **이 순간 놓으면 실제 떨어질 자리**(참 바람으로 낙하 ODE 적분, 지연·탄도계수는 공칭) **− 공식 예측 자리** |

참 바람은 **정답을 만들 때만** 쓰이고 입력에는 들어가지 않는다(teacher–student). 실기에서는 "던진 뒤 예측 vs 실측"으로
같은 라벨이 사후에 생긴다 — 이것이 sim2real 경로다.

### ② 입력 38채널 — `math_utils.tilt_channels` (env·play·fit 공통 정의)

| 그룹 | 채널 | 내용 |
|---|---|---|
| 관측 | 26 | 표적 상대위치·CCIP 오차·착탄 오차 크기(5, 탐지 전 0) · 고도·속도·자세·각속도·낙하시간·남은 시간 등(16) · 직전 속도 명령(4) · 탐지 플래그(1) |
| **tilt 누적** | 10 | roll, pitch, roll·cos ψ, roll·sin ψ, pitch·cos ψ, pitch·sin ψ, vx, vy, 직전 속도 명령 x·y — 각각 **에피소드 시작부터 지금까지의 평균** |
| **gi** | 2 | $(v_t - v_0)/t$ — 접두 평균 가속 |

왜 평균인가: 드론은 바람을 버티느라 기울고, 가속하느라 기운다. 순간값은 섞여 있지만 에피소드 평균에서는 가속 성분이
상쇄된다. yaw 곱은 기체 기울기를 지면 방향으로 돌린다. 속도와 명령을 따로 넣는 이유는 시뮬레이터 속도 루프가 순수 P라
바람이 있으면 "명령 − 실제"가 일정하게 남기 때문(단, 이 신호는 적합의 1.5%뿐 — §4).
왜 gi인가: 에피소드 도중의 접두 평균에는 가속 성분이 남는데, 그 값을 따로 주면 망이 빼 버린다. 정책 전이 회수율 23 → 77%.

### ③ 학습 — `_fit_sl_residual.py --gi --export res_gi.pt`

| 항목 | 값 |
|---|---|
| 망 | MLP 38 → 128 → 128 → 2, ELU, 약 2.2만 파라미터 |
| 입력 처리 | 학습 프레임의 평균·표준편차로 표준화 |
| 손실 / 최적화 | MSE / Adam lr 1e-3, weight decay 1e-4, 코사인 감쇠, 300 epoch, 배치 4096 |
| 프레임 | 화물을 들고 있는 전 프레임 (`--mask attached`; `lastK`로 릴리즈 직전만 쓸 수도 있음) |
| 분할 | **에피소드 단위** 2:1 — 같은 에피소드 프레임은 같은 바람이라 섞으면 정답이 샌다 |
| 결과 | 홀드아웃 $R^2$ **0.668** (관측만 0.436 · +tilt 0.611 · +gi 0.668 · +참 바람 0.998) |

### ④ 내보내기 — `_Exported(net, mu, sd)`: `net((x − mu)/sd)` → 미터. 정규화가 가중치와 함께 실린다.

### ⑤ 주입 — `play.py --sl_residual res_gi.pt --sl_ema 0.3`

매 0.1 s: 관측 → 누적 갱신(에피소드 시작 시 리셋, $v_0$ 래치) → 38 조립 → 회귀기 → $d$ (m) →
**EMA** $\hat d_t = 0.3\,d_t + 0.7\,\hat d_{t-1}$ → $\hat d / 2\,\text{m}$ → clamp ±1 → 행동 채널 5:7.
EMA는 크기를 줄이는 것이 아니라 스텝 간 요동을 누르는 시간 평균이다(예측이 일정하면 출력도 같다). 2 m로 나눈 뒤
환경이 다시 2 m를 곱하므로 결국 **미터 단위 예측이 그대로 예측 착탄점에 더해진다**(±2 m 한계).

환경(`task_env._ccip`): 예측 착탄점 = 공식 CCIP(pos, vel, alt) + 2 m × 채널. 이 점이
(a) **릴리즈 게이트와 첫 교차 판정**에 들어가 "언제 놓을지"를 정하고,
(b) L0가 읽는 **조준 오차 채널 3개**(CCIP 오차 x·y, 착탄 오차 크기)를 채워 L0가 그 점을 표적에 맞추도록 조향한다.
L0의 가중치는 바뀌지 않는다. 착지는 실제 화물로 채점한다.

**예.** 바람이 화물을 서쪽 0.3 m로 민다. 잔차 없음: L0는 공식 예측점을 표적에 맞추고 놓는다 → 0.3 m 서쪽 착지.
잔차 있음: 회귀기가 "서쪽 0.3 m" 예측 → 보정점 = 실제 떨어질 자리 → L0는 공식 예측점이 표적 **동쪽** 0.3 m에 오도록
비행하고, 게이트는 보정점이 표적을 지나는 순간 놓는다 → 표적에 착지.

## 2. 성능 — 정확도 사다리와 그 결과 (DR 1.5, n=600 paired)

| 입력 | $R^2$ | CEP50 | CEP90 | succ@0.5 |
|---|---|---|---|---|
| L0 (잔차 없음) | — | 0.305 | 0.593 | 78.8% |
| 관측 26만 (EMA 0.3) | 0.44 | 0.329 ⛔ | — | 64.7% |
| 관측 + tilt (36) | 0.61 | 0.209 | 0.464 | 86.5% |
| **관측 + tilt + gi (38, 본 방법)** | **0.67** | **0.209** | **0.411** | **89.7%** |
| 오라클 (바람만 앎) | 0.998 | 0.192 | 0.392 | 90.8% |
| 전지적 오라클 (지연·탄도계수까지, 도달 불가) | — | 0.156 | — | — |

$R^2$ 0.67로 오라클 이득의 **85%**. 관측 26만으로는 L0보다 나쁘다 — 부정확한 잔차는 게이트 앞에서 요동만 더한다(Rule 38·41).
CEP50 축의 남은 여지는 0.017 m뿐이고, 여지는 꼬리·시변 바람·라벨 효율·전이에 있다.

## 3. 무엇을 바꾸면 무엇이 달라지나

| 바꾸는 것 | 단계 | 기대 효과 |
|---|---|---|
| 누적 창(지수가중·다중 시간상수) 또는 GRU/TCN로 대체 | ② | $R^2$, 특히 **시변 바람** |
| 정답을 "실현된 착지 − 공식 예측"(사후 라벨)으로 | ① | 낙하 중 바람까지 포함한 **예보**를 배움, 실기 라벨과 동일 |
| 손실에 시간 일관성 항 | ③ | 요동 감소 → EMA 불필요 |
| 평균 + 분산 예측, 불확실하면 0으로 수축 | ③⑤ | 꼬리(CEP90), 미학습 조건, OU에서 자동 off |
| `--mask lastK` | ③ | 놓는 순간의 정확도에 집중 |
| EMA α | ⑤ | 요동 vs 지연 (현재 0.3) |
| 온라인 재귀 갱신(마지막 층) | ⑤ | 투척마다 자기보정 — sim2real |

## 4. 제어기 의존성 — sim2real 대비 ([[research/residual_observability]] §7)

시뮬레이터 속도 루프는 순수 P. PID(PX4)면 "명령 − 실제 속도" 흔적이 사라진다. 그 4채널을 빼고 재적합해도
$R^2$ 0.668 → **0.657**. 적합의 본체는 **자세 평균**(힘 균형, 어떤 제어기든 존재)과 gi다. 다른 제어기에서는
회귀기를 그 비행 데이터로 **재적합**하면 된다(수 분). 비싼 것은 L0의 재학습이지 잔차가 아니다.
