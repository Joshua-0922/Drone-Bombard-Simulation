## 주요 결정 & 발견

- **Vision: 학습=analytic pinhole(YOLO 캘리브레이션 노이즈), 평가=실제 YOLOv8 이원화.** obs
  인터페이스(u_norm, v_norm, conf)는 두 경로가 동일 — real-camera 렌더링을 학습 루프에 넣으면
  Isaac Lab의 병렬화 이점(수천 env)이 죽으므로.
- **Drop = 액션 아님, 스크립트 CCIP 메트릭.** v15와 태스크 스코프 동일 유지(비교 가능성).
  Phase 2 훅(learned residual)만 비활성 스텁으로 wiring.
- **PPO 라이브러리 = rsl_rl** (Isaac Lab 기본, Docker 이미지 기설치, GPU-vectorized).
- **`limit_tilt: 0.26`(Gazebo yaml)은 죽은 설정** — 코드가 어디서도 참조 안 함. 실제 전도
  판정은 `limit_inverted_tilt=1.047`(yaml 미설정, 코드 기본값). Isaac은 1.047만 이식(정확).
- **`_filter_velocity`의 tau 관례 재확인**: 코드 주석은 `τ≈dt·(1/α-1)≈75ms`(20Hz,α=0.4) —
  이전 세션의 "97.9ms 보정"은 다른(틀리지 않았지만 코드베이스 관례와 다른) 연속시간 근사였음.
  이산 재귀식 자체는 어느 쪽이든 동일 — 라벨링만 코드 관례로 통일.
- **Overshoot guard가 success_radius=0.8에서 도달 불가능한 것은 버그 아님.** Gazebo 소스
  (`drone_drop_env.py:775-835`) 재확인 결과 원본도 동일하게 dormant — Rule 10의 의도된 설계
  (0.5 curriculum 전환 시 활성화). 이식 시 "고쳐서" arm_radius를 낮췄다면 Rule 10이 막았던
  정상-접근 오탐을 재도입했을 것 — **Rule 16으로 일반화**(시뮬레이터 이식 시 dormancy는
  버그 추정 전에 원본 소스로 먼저 검증).
- **추력 계산 라벨 오류 발견·정정**: T/W=2.0은 무탑재(2.07kg) airframe 고정 스펙인데,
  탑재질량(2.17kg) 기준으로 잘못 라벨링해 42.6N이 나왔었음 → 40.6N으로 정정. 실측 데이터
  아님(SITL 추정), 컨트롤러 accel clamp가 먼저 발동해 실제 상한 미도달 확인.
