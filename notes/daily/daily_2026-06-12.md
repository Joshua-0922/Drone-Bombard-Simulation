## 주요 결정 & 발견

### EKF East 반전 패턴 확인

PX4 SITL + Gazebo Harmonic 조합에서 EKF East = -Gazebo_East. `drone_controller_node.py`는 line 72에서 의도적으로 y를 반전하여 이를 보정:

```python
self.target_pos = [msg.x, -msg.y, -msg.z]
```

이 반전이 있기 때문에 NED(+1,+1) 순항 명령이 실제 Gazebo NE 방향 비행으로 이어짐. 그러나 proximity target 좌표는 이 보정을 반영하지 않아 8시간 동안 proximity가 한 번도 작동하지 않음.

**좌표 변환 공식:**
```
Gazebo ENU (East=X, North=Y) → EKF NED (North=Y, East=-X)
마커 Gazebo ENU (11, 10) → EKF NED (10, -11)
```

### YOLO 실제 마커 탐지 conf

드론이 마커 직상방 통과 시: conf **0.10–0.35** (낮고 단발적). False positive와 conf 범위 겹침 → conf 단독으로는 구분 불가. 공간 필터(pixel_dist ≤ 200px)가 핵심 차별자.

### RL env가 YOLO를 직접 관리함

`drone_drop_env.py`가 YOLO를 `_infra_procs`로 spawn·kill 관리. 수동으로 추가 기동 시 이중 노드 문제 발생 → `_infra_procs` 밖의 YOLO는 env가 kill하지 못해 영속적 중복 발생.
