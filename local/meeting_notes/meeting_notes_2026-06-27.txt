*  PART 1 — Fine-tune 17k step 의 한계 분석
********************************************************************************

  사용자 분석 (정확):
    "사용자 의도 (지나치는 현상 해결) 안 됨"
    "별로 달라진게 없는거 같은데?"

  Claude 분석:
    1. v9a 의 처방 magnitude vs v8 baseline:
       - v8 평균 terminal reward = +30 ~ +80 per ep
       - v9a 의 처방 영향:
         · w_dist 1.5 의 누적 (50 step 비행): +5 (지나치는 시점 -1.4 포함 → 순 +3.6)
           = terminal +30 의 ~12%
         · drop_angaccel penalty 0.5 × max_accel 2 rad/s² = -1.0 per ep
           = terminal +30 의 ~3%
       - 처방 총 영향 = +2.6 (terminal 의 8.7%)
       → 17k step 으로는 정책 본질 변경 어려움.

    2. v8 의 강한 toss prior (303k 학습):
       - critic network 가 toss trajectory 의 high reward 확신
       - actor network 가 toss action sequence 강하게 학습
       - fine-tune 의 작은 처방 신호가 이 prior 흡수

    3. fine-tune step 수의 효과 curve (예상):
       - 0 ~ 10k:    정책 초기 흔들림 (adapter loss spike)
       - 10k ~ 50k:  새 reward 적응 시작
       - 50k ~ 100k: 본질 행동 변화 가능
       - 100k +:    new local optimum 정착

    → v9a 의 17k 는 0~10k 흔들림 직후. 본질 변화 시작 전.

  새 Rule (Issue #025 등록):
    Fine-tune step 수 권장 범위:
      - 최소 50k step (baseline 의 16.5%) — 처방 본질 효과 보이려면
      - 권장 100k step (33%) — 안정 신뢰성
      - 최대 200k step (66%) — 완전 새 정책 가능


********************************************************************************
*  PART 2 — 사용자 두번째 처방 후보 정리
********************************************************************************

  사용자가 직접 두번째 처방 3 가지 후보 제시 (각 위험성 자각):

  옵션 1 — target 거리 제한 (안전: ★★★):
    drone 이 어느 거리 이상으로 target 과 가까워지면 penalty
    → drone 이 target 위 까지 안 가게 강제
    → early shot (조준 후 toss) 학습 유도

    구현:
      ```python
      if d_xy < target_distance_min:
          reward -= scale * (target_distance_min - d_xy)
      ```

  옵션 2 — 시간 패널티 강화 (위험: ★):
    사용자 자각: "최단 시간 조건을 강화 < - 기존 학습이 정말 잘 된 경우에만 사용가능.
    그 외에는 발산 가능성"

    구현:
      ```yaml
      reward.w_time: 0.01 → 0.05
      ```
    위험: per-step density 변경 → SAC entropy 발산 (Round 4 교훈)
    v9 단계 적합 안 함

  옵션 3 — drop 좌표 강제 (강력: ★★):
    drop 시점이 임의 사용자 정의 좌표 에서 멀어질수록 penalty
    → 강제로 어느 거리에서 발사하게끔
    → drop 좌표에 맞춰 드론이 속도 조절

    구현:
      ```python
      if drop_triggered:
          reward -= scale * ||drone_xy - desired_drop_xy||
      ```
    위험: 좌표 결정 자체가 학습 prior 강제

  안전 순위: 1 > 3 > 2


********************************************************************************
*  PART 3 — w_dist 와 drop_angaccel 정확한 의미 (사용자 재확인)
********************************************************************************

  사용자 질문: "w_dist와 drop_angaccel은 각각 정확히 무슨 보상이야?"

  Claude 답 (정확):

  3-1. w_dist (= 1.5):
    매 step (drop_drop_env.py line 1110):
      r3_dist = w_dist * (d_xy_prev - d_xy)
      reward += r3_dist

    의미: drone 의 horizontal distance to target 의 변화에 weight 곱한 reward.
    가까워지면 +reward (positive), 멀어지면 -penalty (negative).

  3-2. drop_angaccel_penalty_scale (= 0.5):
    drop 시점에 (1회만):
      hist = list(self._ang_vel_history)  # last 5 step ang_vel
      max_accel = max(||hist[i] - hist[i-1]|| for i in range(1, len(hist)))
      reward -= drop_angaccel_penalty_scale * max_accel

    의미: drop 직전 5 step 의 가장 큰 각가속도 (인접 step ang_vel diff magnitude) penalty.
    toss 의 갑작스러운 pitch back 차단.

  v9a 측정값:
    | EP | max_ang_vel | max_accel 추정 | penalty |
    | 1  | 2.47 rad/s  | ~1.5 rad/s²    | -0.75   |
    | 2  | 1.87        | ~1.2           | -0.60   |
    | 3  | 2.39        | ~1.4           | -0.70   |
    | 4  | 1.96        | ~1.3           | -0.65   |
    | 5  | 1.83        | ~1.2           | -0.60   |
    평균 penalty ≈ -0.66 (terminal reward +30 의 2%)

*  PART 4 — payload distance reward 의 의도와 한계
********************************************************************************

  사용자 질문: "혹시 이쯤에서 아예 새로운 모델을 생각해봐도 돼?
                이거와 별개로 별도로 다루는거야"

  분석:
    payload distance reward 의 사용자 의도 = payload trajectory monotonic 보상
    → "drone 이 x 위에서 떨구는 거나, x 도달 전 조준해서 떨구는 거나 reward 동일"
    → drone 의 위치 무관, payload 가 target 향해 가면 OK

    가능한 학습 결과 (학습 잘 되었다는 가정):
      A. hover-drop (사용자 예상): drone 이 target 위 멈춤 + drop ← 40-50% 가능성
      B. early shot (조준): drone 이 target 도달 전 ballistic 활용 ← 30% 가능성
      C. 부드러운 toss: 약화 ← 15%
      D. toss 유지 (local optimum): ← 10%
      E. 예상치 못한 발견: ← 5%

  B (early shot) 가능성 ↑ 방향:
    추가 처방 (사용자 답: A + α):
      - 처방 A (payload distance + ang_accel) 진행
      - 추가 α: CCIP 보상 활성 (w_prediction 0 → 5.0) — ballistic 정확도 학습 강화

  현실: detach 후 payload trajectory 추적 안 함 → Issue #027 (큰 변경)

*  PART 9 — 10 EP 통계 비교 (v8 vs v9a 313k vs v9a 432k)
********************************************************************************

  사용자 의문: "v9와 비교해서 v9a 313k가 더 좋은게 맞아?"
    → 5 ep 표본 운 의심
    → 10 ep 평가 진행 ("진행해봐")

  결과:
    | 모델              | step | drops | success≤2m | mean err | hover_timeout |
    | v8 (96bokgae)     | 217k | 10/10 | 5/10 = 50% | 2.002m   | 0             |
    | v9a 313k          | 313k |  9/10 | 3/9 = 33%  | 2.006m   | 1             |
    | v9a 432k (5 ep)   | 432k |  3/5  | 2/3 = 67%  | 1.96m    | 2 ⚠️          |

  통계 해석 (binomial SE):
    - 5 ep 의 SE ≈ 22% (samples=5 시)
    - 10 ep 의 SE ≈ 16%
    - 이전 5 ep 100%/80% = 표본 운 (실제 50%/33%)

  핵심:
    - v8 가 v9a 보다 success 17% ↑ (50% vs 33%)
    - mean err 둘 다 ≈ 2.0m (success_threshold 경계)
    - **v8 = best baseline 확정**
