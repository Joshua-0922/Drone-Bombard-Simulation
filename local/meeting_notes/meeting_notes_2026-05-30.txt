  버그 메커니즘:
    1) 이전 epi가 위치 X에서 종료
    2) Reset: _gz_reset_poses()로 드론을 (0,0,0)으로 teleport
    3) _start_episode() → _wait_for_cruise() 대기
    4) Step 1 시작 → pos_enu 읽음
    5) 그러나 PX4 새 position 메시지 미도착 → pos_enu 잔류
    6) d_impact = stale 데이터 기반 → ≤ 3m → auto_drop 발동
    7) drop_calculator도 stale 데이터 → 가짜 small drop_error

  해결: drone_drop_env.py reset()에서 state lock 안에 명시적 초기화 추가
    self._node.pos_enu = np.zeros(3, dtype=np.float32)
    self._node.vel_enu = np.zeros(3, dtype=np.float32)
    self._node.ang_vel = np.zeros(3, dtype=np.float32)
    self._node.roll = 0.0
    self._node.pitch = 0.0
    self._node.pixel_coords = np.zeros(3, dtype=np.float32)

  → Step 1에서 PX4 갱신 전이라도 (0,0,0)으로 인식 → d_impact ~14.9m → auto_drop 안 됨

    step  7492 success(4.17m) → 다음: 65m, 13m, 15m, 16m, 51m
    step 17160 success(3.23m) → 다음: 76m, 22m, 20m, 3.6m, 31m

    step 95206 success(4.97m) → 다음: 73m, 15m, 12m, 8m, 14m

  원인 (4가지 메커니즘):
    1) Critic overshoot: 큰 보상이 Q-value 일시 폭증
    2) Policy gradient over-correction: actor가 success state로 끌려감
    3) Replay buffer 압도: success 1건 vs 실패 426건 → 다시 평균으로 회귀
    4) High entropy exploration: ent_coef 0.7+로 success 행동 깨뜨림

********************************************************************************
*  PART 7 — 함수 분석 + 4가지 안전장치 도입
********************************************************************************

  함수 특성 검토 (사용자 질문):
    - Sigmoid: (0,1) 유계, S자, 대칭
    - Tanh: (-1,1) 유계, sigmoid scale 변형
    - Softmax: 다수 입력 비교용 (단일 reward에 부적합)
    - Min-Max normalization: 선형, outlier 민감

  코드 내 exp() 5곳 분석:
    1) Proximity bonus:  30 * exp(-0.15 * d_xy)        — 음수 지수, 안전
    2) Precision reward: 100 * exp(-0.2 * d_error)     — 음수 지수, 안전
    3) Prediction bonus: 20 * exp(-0.1 * gap)          — 음수 지수, 안전
    4) Altitude penalty: 지수 (양수) — Sigmoid로 교체
    5) Impact shaping:   0.4 * exp(-0.05 * d_impact)   — 음수 지수, 안전

  발견: 음수 지수 exp(-k*x)는 출력 (0, max]에 자연 유계 → 발산 불가.
        양수 지수만 위험. 알티튜드 페널티만 양수였음.

  4가지 안전장치 도입:

    1) Sigmoid 고도 페널티 (지수 폐기)
       penalty = -alt_penalty_max * sigmoid(k * (alt - mid))
       max=50, mid=30m, k=0.15
       거리별: 15m→-4.7, 30m→-25, 50m→-47.5, 100m+→-50 (포화)

    2) max_altitude truncate 50m + 페널티 -15
       비행 중 극단 상승 차단
       페널티 -15 (timeout 동일) — "climb-out" exploit 방지

    3) PER priority 상한 30
       priority = min(30, (|reward| + eps)^alpha)
       이론 max reward 200 → priority ≈ 24, cap 30은 충분

    4) Hard cap [-200, +300] + warning
       drone_drop_env.py step 끝에 추가
       reward 범위 밖이면 print + np.clip
       방어적 안전망. 정상 학습엔 영향 없음.

  수정 파일:
    hyperparams.yaml:    alt_penalty_max/mid/k, penalty_max_altitude,
                         per_priority_max 추가
    drone_drop_env.py:   지수→sigmoid, max_altitude truncate 부활,
                         hard cap + warning
    train_sac.py:        PrioritizedReplayBuffer에 priority_max 추가
