증상
  - 학습 켜면 90초 후 "Timed out waiting for PX4 readiness" 만 출력하고 죽음
  - PX4 stdout/stderr 가 /dev/null 로 흘러 silent failure
  - 진짜 원인 안 보이는 상태로 시간 낭비

  - drone_drop_env.py:1131 의 px4_log = open(os.devnull, 'w') 를 임시로

                   /opt/PX4-Autopilot/build/px4_sitl_default/rootfs/etc/init.d-posix/airframes)
      ERROR [px4] Startup script returned with return value: 256

원인
  - PX4 SITL 의 airframe 등록은 두 단계로 분리됨
      * 소스(ROMFS): 4015 (base) + 4016~4019 (r0~r3, 멀티 인스턴스) — 모두 존재

    → r0 이 rootfs 에 없어 모든 학습 시도가 silent fail

해결 옵션 비교
  A. PX4 풀 재빌드 (make px4_sitl_default)         — 15~20분, 영구
  B. ROMFS → rootfs 로 4016~4019 cp                — 즉시, 컨테이너 라이프타임만 유효
  C. drone_drop_env.py 를 base 모델만 쓰도록 수정   — 즉시, 멀티 인스턴스 학습 못 함

════════════════════════════════════════════════════════════════════════════════
 ✅ H1.  Reward Scale 평탄화   [적용 완료 + 검증]
════════════════════════════════════════════════════════════════════════════════
적용 :  옵션 A — terminal 만 축소 (w_drop_base 50→20, jackpot 100→30, instability 50→15)
검증 :  critic_loss 가 일시 폭주(49.1) 후 안정화(32.9)로 떨어짐. terminal spike

회의 :  본 학습 진입 OK 받기.  더 줄일 필요 있는지 의견은 받되, 추가 변경은 보류 권장.

----- 이하 원본 의사결정 자료 (참고용) -----

현재 reward 분포
  step reward          : r2 ≈ -0.05 ~ -0.5,  r3 ≈ 0.1 ~ 2
  crash penalty        : -10
  target_lost penalty  : -10
  overspeed penalty    : -8
  drop jackpot         : +100   ← terminal spike
  instability penalty  : -50    ← terminal spike
  w_drop_base*exp(…)   : 최대 +50

문제
  Critic 신경망 한 개가 ±0.5 영역과 ±100 영역을 동시에 fit 해야 함.
  결과적으로:
    - terminal spike 에 Q 추정이 끌려가 variance 증가
    - actor 가 noisy Q 에 끌려 unstable
    - 학습 초반에 더 두드러짐 (이번 5k 학습에서 actor_loss 가 -3 → -21
      급변한 것도 이 영향일 가능성)

옵션
  A. terminal 만 축소
       w_drop_base 50 → 20,  r_success_jackpot 100 → 30,
       penalty_instability 50 → 15
     [장점] 코드 변경 최소.  [단점] step reward 와 격차는 여전히 큼.

  B. 전체 normalize
       step reward 를 0.1~1 범위에 맞추고 terminal 도 동등 스케일로
       (모든 가중치 등비례 조정)
     [장점] 가장 깔끔.  [단점] 모든 reward 가중치 재튜닝 필요.

  C. VecNormalize(norm_reward=True) 추가 (SB3 표준 래퍼)

  H2 (action[4] 제거) 가 "한 번의 drop 의 정확도 향상" (23.95→14.87m, 38%개선) 은

원인 추정
  - CCIP auto_drop_threshold = 2.0m 가 충분히 가까워야 drop 발생
  - 학습 초반엔 d_impact 가 평균 122m → drop 거의 못 함

  B. d_impact reward 강화 — w_impact 2.0 → 5.0, k_impact 0.05 → 0.1
       drop 안 일어나도 "drop 했으면 좋았을 위치" 에 가까울수록 큰 보상.
  C. Terminal reward 시간적 분할 — drop 5 step 전부터 progressive reward 분배
       sparse → dense 화. 구현 복잡.
  D. 본 학습 (1M step) 그대로 진행 — drop_count 가 자연스럽게 늘어나는지 관찰
