********************************************************************************

  발견 동기: v9 처방 (drop ang_vel penalty) 검증 위해 v8 의 drop_episodes 분석.

  충격 결과:
    v8 학습 500 ep sample 의 obs[:, 6:9] (ang_vel 부분):
      mean: 0.000000
      max:  0.000000
      >0 인 비율: 0.00%
    → 모든 step 의 ang_vel obs 가 정확히 0.

  root cause:
    PX4 의 /opt/PX4-Autopilot/src/modules/uxrce_dds_client/dds_topics.yaml 에서

      - topic: /fmu/out/vehicle_status

  의미:
    v8 학습 전체가 ang_vel obs 없이 진행됨에도 80% success 달성.

********************************************************************************
*  PART 4 — v8 toss 전략 분석 (Issue #026)
********************************************************************************

  사용자 GUI 시각 검증으로 정책 행동 발견:
    1. drone 이 (0, 0, 0.24) spawn → cruise alt 5m
    2. 정책이 cruise 명령 (NW) 무시 + target (4, 3) NE 방향 비행
    3. drone 이 marker 를 지나친 위치 (예: (5, 4)) 까지 감
    4. 그 위치에서 멈춤 + 몸을 marker 방향으로 기울임 (pitch back)
    5. detach → payload 가 forward momentum 으로 marker 향해 toss
    → 모든 ep 일관 = 정책 완전 수렴

  사용자 평가:
    "이게 나쁜건 아닌데 우리가 막연하게 생각하는 그런 방향은 아니잖아?"
    "이렇게라도 학습이 되었다는 점은 고무적이야"

  사용자 두 가설:
    가설 1 — 탐험 부족 (local optimum): 부분 정확
    가설 2 — 환경이 두 행동 (hover-drop vs toss) 구분 못 함: 가장 본질 (root cause)

  잘못된 1차 진단 (정정):
    내가 처음 "hover_drop_block_threshold = 0.0 이 hover-drop 차단" 이라고
    잘못 분석. yaml comment: "0 = 비활성 (모든 drop 허용)". hover-drop 허용됨.

  진짜 root cause:
    1. auto_drop_threshold = 2.0 (ballistic CCIP-based 자동 drop)
    2. sparse reward (terminal drop_err 만)
    3. target NE vs cruise NW
    4. detach 후 ep 즉시 종료 (payload trajectory 평가 X)


********************************************************************************
*  PART 5 — v9 처방 결정 (사용자 의도)
********************************************************************************

  사용자 처방 1 — drop 시점 drone 각속도 변화 penalty:
    "drop 시의 드론의 각속도 변화에만 제한이 있으면 될 거 같아"
    의도: toss 의 급격한 pitch back 차단, 정책이 부드러운 drop 학습

    측정 방법 결정 (E):
      drop trigger 시 직전 5 step (`drop_angaccel_window_n=5`) 의
      인접 ang_vel diff magnitude 의 max (`drop_angaccel_penalty_scale=0.5`)

    구현 (drone_drop_env.py):
      ```python
      from collections import deque
      self._ang_vel_history = deque(maxlen=6)
      # step() 매 step: self._ang_vel_history.append(ang.copy())
      # drop trigger 시:
      hist = list(self._ang_vel_history)
      max_ang_accel = max(||hist[i] - hist[i-1]|| for i in range(1, len(hist)))
      reward -= drop_angaccel_penalty_scale * max_ang_accel
      ```

    prerequisite: Issue #024 (ang_vel callback fix)

  사용자 처방 2 — payload distance reward:
    "payload 가 처음부터 끝까지 가까워 지면 가산점, 멀어지면 패널티"

    분석 결과: 기존 r3_dist (w_dist * (d_xy_prev - d_xy)) 와 본질적으로 동일.
    - attached 동안 drone == payload (offset 0.14m 작음)
    - detach 후 ep 즉시 종료 → payload ballistic 추적 안 됨 (Issue #027)

    선택: 옵션 A — w_dist scale 증가 (1.0 → 1.5)
      - 단순, 효과 명확
      - monotonic distance reduction 강화

    폐기: 옵션 B (detach 후 payload tracking) — 큰 변경, Issue #027 별도 안건

  scale 결정:
    payload_distance_reward_scale (= w_dist) = 1.5
    drop_angaccel_penalty_scale = 0.5
    drop_angaccel_window_n = 5

  학습 step:
    100k (의도) → train_sac 의 timesteps=400000 (= v8 의 303k + 100k 추가)
