# RAD v1 Phase 1 학습 주간 보고 (2026-06-30 ~ 2026-07-05)

---

## 1. 이번 주 목표

RAD v1 이라는 새 프레임워크로 드론이 목표 지점(sphere) 에 진입하는 정책을 학습시키는 것이 목표. 300,000 step 학습을 완주하면서 최종적으로 sphere 진입 성공률 90% 이상 달성이 성공 기준.

이전 프레임워크 (v8) 는 학습이 잘 됐지만, RAD v1 은 새로 설계한 것이라 처음부터 다시 검증이 필요했음. 주요 차이점은 관측 방식이 바뀌었고 (드론 자기 시점 기준), 매 에피소드마다 시작 방향이 랜덤이며, 목표가 단순 투하가 아니라 sphere 진입 + 7가지 부가 조건으로 더 복잡해짐.

---

## 2. 시행착오 이야기

### 6월 30일 — 첫 시도 (v1)

원래 설계 그대로 300k 학습 시작. 짧은 사전 테스트 (5k) 는 문제 없었기 때문에 진행.

**결과**: 62,000 step 부근에서 학습이 갑자기 죽음. 정책 신경망 출력이 수치 오류 (NaN, "숫자가 아님") 로 붕괴. 학습 프로세스 강제 종료됨.

이 상황이 발생하면 학습 자체가 crash 되므로 처음부터 다시 시작해야 함. 원인 진단이 필요했음.

**진단 시도**: 여러 가설을 세웠지만 확답 못 함. 관찰된 사실만으로는 "학습이 발산 방향으로 흐르다가 어느 순간 폭발" 이라는 큰 그림만 보임.

### 7월 2일 — Self-healing 매커니즘 도입 (v2)

원인이 확실하지 않으니 **먼저 안전장치** 를 만들자는 방향. 학습 중에 이상 신호를 감지하면 자동으로 복구하는 매커니즘 두 가지 도입:

**첫째, 학습 신호 크기 제한**. 신경망이 학습할 때 받는 신호(gradient) 가 너무 크면 자름. 폭발적 업데이트 방지.

**둘째, 자동 복원 (weight rollback)**. 신경망 weight 가 수치적으로 이상해지면 직전 상태를 저장해뒀다가 복원. "자동 저장/불러오기" 처럼.

**결과**: 171,000 step 에서 다시 NaN abort. 안전장치가 발동하지 않은 채 실패.

발동 안 한 이유는 NaN 이 학습 도중이 아니라 실제 드론 조작 순간에 발생했기 때문. 우리 안전장치는 학습 단계에만 감시하고 있었음.

교훈: **Self-healing 은 필요하지만 근본 원인은 다른 곳** 이라는 확인.

### 7월 3일 — Curriculum + 자동 재도전 (v3)

한 번에 어려운 목표를 학습 시키면 안 됨. 쉬운 단계부터 시작해서 성공하면 다음 단계로 올라가는 **커리큘럼 학습** 도입. 세 단계로 나눔.

여기에 신규로 **자동 재도전 (regression)** 도 추가. 다음 단계에서 계속 실패하면 이전 단계로 자동 복귀해서 재학습. 사람이 개입 없이 학습이 스스로 되돌아올 수 있는 매커니즘.

**결과**: Stage 1 (가장 쉬운 단계) 조차 통과 못 함. 정책 성공률이 75% 에서 정체.

더 파고 들어보니 학습 signal 자체가 발산 방향. 커리큘럼만으로는 부족.

### 7월 3일 (같은 날) — 보상 크기 축소 (v4)

발산 방향이 지속되니 근본 원인을 보상 크기로 봄. Crash 페널티 -50, hover 페널티 -30, truncation 페널티 -15 등 여러 페널티 값이 큰 편이었음. 이걸 각각 절반 이하로 축소.

**결과**: 학습 안정성 크게 향상. 이전 대비 발산 압력이 절반 이하로 줄어듦. Stage 1 통과 성공. 하지만 이번엔 Stage 2 에서 stuck.

Stage 2 에서 문제는 정책이 계속 **hover (가만히 있음)** 상태로 실패. Hover 65%. 정책이 위험한 시도 대신 안전한 실패를 선택하는 local optimum 에 빠짐.

Stage 1 → Stage 2 진입 → hover 반복 → 자동 재도전 발동 → Stage 1 복귀 → 재학습 → Stage 2 진입 → 또 hover... 이런 사이클이 반복.

### 7월 4일 — Stage 조건 완화 (v5)

Stage 2 갭이 너무 커서 실패라 판단. Stage 2 반경을 5m → 5.5m 로 넓히고 crash 조건도 완화.

**결과**: 여전 hover 65%. 갭 완화가 문제 아님. **정책이 목표를 향해 이동하는 학습 자체를 안 하는 게** 문제.

### 7월 4~5일 — 근본 접근 (v6)

여러 시도가 실패해서 접근 자체를 바꿈. Fact 확인 우선 원칙.

**세 가지 변경**:
- 시작 방향 랜덤 범위를 ±90° 에서 ±45° 로 축소 (학습 어려움 완화)
- Hover 페널티를 -10 에서 -30 으로 강화 (안전한 실패 선호 회피)
- **매 에피소드 시작 시 드론 위치를 로그하는 도구 추가** (사실 확인 목적)

특히 세번째가 이번 주의 핵심 도구. 실제로 정책이 어디서 시작하는지 확인하기 위한 것.

**결과**:
- Stage 1 통과 (14,000 step)
- **Stage 2 통과 (27,800 step)** — v4, v5 가 못 넘긴 지점 돌파. Hover 65% → 1% 로 급감. Hover 페널티 강화 극적 효과 확인.
- **Stage 3 (진짜 목표 조건) 진입 → 완전 실패 (성공률 0%)**
- 자동 재도전 발동 → Stage 2 복귀 → 재학습 → Stage 2 재통과 → Stage 3 재도전... 이 사이클 반복 예상.

**결정적 발견**: 새로 도입한 로그로 실제 정책 시작 위치를 확인. 매번 거의 같은 곳 (drone spawn 위치 근처, 목표까지 5.1m 거리) 에서 시작. Cruise 로직으로 이동하는 거리는 0.15m 로 매우 짧음.

이 사실을 우리 커리큘럼 stage 설계에 대입하면:

| Stage | Sphere 반경 | 시작 거리 5.1m 대비 | 정책이 학습해야 하나? |
|---|---|---|---|
| Stage 1 | 6.0m | 이미 반경 안 | 아니오 |
| Stage 2 | 5.5m | 이미 반경 안 | 아니오 |
| Stage 3 | 4.53m | 반경 밖 | 예 |

즉 **Stage 1, 2 는 정책이 아무것도 안 해도 성공하는 조건**. 정책은 이 두 단계에서 아무것도 배우지 않고, Stage 3 에서 처음으로 이동 학습이 필요한데 능력 없음 → 완전 실패.

이건 v1 부터 v6 까지 몰랐던 근본 문제. 정책이 stage 통과할 수 있으니 학습 되는 줄 알았지만 사실은 spawn 위치가 이미 목표 안이라 자동 통과. 실제 정책이 학습해야 할 이동거리는 **0.47m** (5m → 4.53m) 매우 짧음.

## 3. 주요 발견 사항

### Self-healing 매커니즘 유효
Gradient clipping + weight rollback 으로 학습 안정성 향상. 다만 근본 문제는 fix 못 함.

### Curriculum + 자동 재도전 매커니즘 유효
쉬운 단계부터 학습 + 어려우면 되돌아가기 매커니즘 정상 작동. 자기수복 학습 개념 실현.

### 보상 크기 축소 큰 효과
Crash, hover, truncation 페널티를 축소하니 학습 안정성 크게 향상. Q 값 spread 43% 축소.

### Hover 페널티 강화 극적 효과
V5 → V6 사이 hover timeout 65% → 1% 로 급감. 정책이 안전한 실패 대신 능동적 시도 하도록 유도 성공.

### 진짜 원인 확정 — 커리큘럼 stage 설계 결함
Stage 1, 2 반경이 정책 시작 위치보다 넓어서 학습 유도 못 함. 실제 학습해야 할 이동거리는 매우 짧음. Stage 재설계 필요.

### Cruise 로직 이해 정정
학습 도중에 "cruise 가 안 된다" 라고 오진단했지만 실제로는 정상 작동. 이동 거리가 짧을 뿐. 이전 프레임워크 (v8) 부터 동일한 로직.

| 14,011 step | Stage 1 → Stage 2 |

이대로 두면 Stage 2 ↔ Stage 3 사이클만 무한 반복. Stage 3 자체가 정책 능력 밖.

## 5. 이번 주 개발한 도구/매커니즘 (재사용 가능)

- **Self-healing SAC**: 학습 신호 크기 제한 + 자동 복원
- **Curriculum + 자동 재도전 시스템**: 단계별 학습 + 실패 시 되돌아가기
- **Initial 위치 실측 도구**: 매 에피소드 시작 위치 로그 → 이번 주 근본 원인 파악의 결정적 도구
- **에피소드 종료 원인 분류기**: crash, entry, timeout, hover 등 분류해서 통계

## 6. 다음 단계

### 즉시 진행

**커리큘럼 stage 재설계**:

정책 시작 위치 (target 거리 5.1m) 를 반영하여 stage 반경을 좁게 재설계.

```
현재 (문제):        →  개선 (제안):
Stage 1: 6.0m       →  Stage 1: 4.80m
Stage 2: 5.5m       →  Stage 2: 4.65m
Stage 3: 4.53m      →  Stage 3: 4.53m (design 목표)
Stage 4: + 부가 조건 →  Stage 4: + 부가 조건 3개
Stage 5: + 전체 조건 →  Stage 5: + 전체 조건 7개
```

이렇게 하면 Stage 1 부터 정책이 실제 이동 학습이 필요하고, 매 단계 갭이 매우 작아서 (0.15m) 완만한 학습 가능.

### 이후 (Phase 2)
Phase 1 학습 완료 후 Phase 2 (Drop, 정밀 투하) 학습. Phase 1 정책을 시작점으로 사용.

### 장기 계획
- 진행 상태에 따라 자동으로 커리큘럼 조정
- 보상 shaping 재검토 (dense signal 강화)
- 여러 환경 동시 학습 (학습 속도 개선)
