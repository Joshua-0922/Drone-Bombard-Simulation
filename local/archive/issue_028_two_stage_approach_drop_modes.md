 1. 문제점
================================================================================

  v8 의 toss 전략 + v9a 의 fine-tune 미달성 분석 결과:

  - v8 정책이 단일 strategy (= toss) 로 완전 수렴
  - 사용자 의도 (hover-drop 또는 더 자연스러운 drop) 미달성
  - Issue #026: 환경의 hover-drop vs toss 구분 부족 — 한 정책 안에서 두 dynamics
    (cruise + precision drop) 가 충돌

  근본적 한계:
    - 단일 reward + 단일 정책 → 단일 strategy 만 학습
    - target (4, 3) 절대좌표 고정 → 일반화 어려움 (다른 위치에 transferable X)


================================================================================
 2. 사용자 제안 (thoughts 원문 요약)
================================================================================

  2-1. 상대좌표 기반:
    - 카메라로 인지한 target 과의 상대좌표 사용
    - 매 step 마다 새 target 좌표 업데이트
    - 절대좌표 → 상대좌표 → 일반화 가능

  2-2. 2 단계 모드 분리:
    단계 1 (접근 모드):
      - target 일정 거리 (x² + y² + z² < R) 안으로 접근
      - 제약 조건만 만족하면서 자유 비행 (최대속도, 최종속도, 최대각속도,
        상대속도 방향 등)

    단계 2 (투하 모드):
      - target 일정 거리 안 진입 시 시작
      - payload 의 예상 투하지점 예측 + 몸 비틂 (최대 각속도/각가속도 준수)
      - 원하는 지점에 투하
      - 시간 제한 확실 + 몸 비트는 정도 최소화

  2-3. 학습 단계:
    Step 1. 단계 1 학습 — 다양한 접근 모델 풀 생성 (단계 2 의 base 들)
    Step 2. 단계 1 의 한 모델 선택 → 단계 2 학습
            (drop 모드 추가 + drop reward 시작)
    Step 3. 단계 2 성공 → 단계 1 확장 (다양화) → 단계 2 다시 학습 → 융합

  2-4. 융합 전략:
    - 단계 1 의 두 모델을 확률적으로 선택 (50:50)
    - 단계 2 학습 시 처음에는 헤맴 → 나중에 우수 학습 기대
    - 안 되면 단계 2 실패 시 단계 2 비중 높임 (제한 둠)

  2-5. 자각된 우려 (사용자 직접):
    - 단계 1 → 단계 2 reward 체계 급변 의 영향 (괜찮을 것 같다 추측)
    - 융합 과정의 정책 문제
    - 시작 단계부터 toss 의 불확실성 으로 고생 가능


================================================================================
 3. 분석 — 장점
================================================================================

  3-1. 상대좌표:
    target 위치 무관 학습 → v8 의 (4, 3) 절대좌표 한계 해결.
    일반화 가능 (Issue #018 Vision-based 도 같은 방향).

  3-2. 단계 분리:
    두 dynamics (cruise vs precision drop) 의 학습 신호 충돌 해결.
    v8 의 toss = 두 dynamics 가 한 정책으로 섞임 → 단계 분리로 분명히 분리.

  3-3. 다양 접근 모델 풀:
    단일 strategy (= toss) 의 local optimum 회피.
    Issue #026 의 가설 1 (탐험 부족) 의 직접 해결.

  3-4. 확률적 융합:
    curriculum learning 의 자연스러운 형태.
    작은 단계 변화로 정책 전이 (catastrophic forgetting 위험 낮춤).


================================================================================
 4. 분석 — 단점 / 우려
================================================================================

  4-1. 구현 복잡성:
    env 가 두 모드 state machine 필요.
    action space 또는 reward 가 모드 별로 다를 수 있음.
    drone_drop_env.py 큰 refactoring.

  4-2. 단계 경계 (모드 전환 시점):
    "거리 안 진입" 의 정확한 시점 결정.
    전환 시점에 정책의 reaction 어떻게 학습할지.

  4-3. 단계 1 모델 풀의 크기/다양성:
    너무 적으면 단계 2 가 한 풀에 over-fit.
    너무 많으면 단계 2 학습 시간 폭증.

  4-4. 융합 안정성:
    단계 1 의 두 모델 사이 transition smooth 해야.
    확률적 mixing 시 정책 발산 위험.

  4-5. 카메라 의존:
    `use_vision: false` 인 현재 환경에서 시작 어려움.
    Vision 환경 (Sensors plugin 추가 → x_marker_world_vision.sdf) 필요.
    Issue #018 와 연동.

  4-6. 사용자 자각 우려:
    - 단계 1 → 2 reward 체계 급변 — 단계 1 영역에서는 단계 2 reward = 0
      이므로 영향 거의 없을 것으로 추정 (사용자 추측 동의)
    - 융합 과정 — 확률적 mixing 으로 점진 적응 가능
    - toss 불확실성 — 단계 분리로 일부 해결, 단계 2 의 reward shaping 잘 해야
