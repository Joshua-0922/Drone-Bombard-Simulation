================================================================================
 이 가이드의 목적
================================================================================

학습이 끝난 뒤, 학습된 모델이 실시간으로 obs를 보고 비행하는 모습을
Gazebo GUI에서 직접 관찰한다.

방식: deterministic evaluate — 학습된 모델이 매 step 현재 상태를 보고
action을 결정 (closed loop). 실제 배포와 동일한 동작.

주의: 이전의 "drop episode replay" 방식은 open loop (저장된 action을
순서대로 넣기)라 원래 궤적과 완전히 달라짐 → 사용하지 않음.

향후 추가될 수 있는 항목:
  [ ] 타겟(x 마커) 위치 변경 테스트
  [ ] 바람/외란 조건 테스트
  [ ] 다른 고도/속도 출발 테스트
  [ ] milestone 간 비교

원칙:
  1. 명령어를 복사-붙여넣기만으로 실행
  2. Gazebo GUI에서 드론 행동을 직접 관찰
  3. "눈으로 봤을 때 납득이 되는가"를 판단

--------------------------------------------------------------------------------
 Step 2. evaluate 실행
--------------------------------------------------------------------------------

에피소드 수와 모델 경로를 확인한 뒤 전체를 붙여넣기.
EPISODES=5 는 원하는 에피소드 수로 변경 가능.

EPISODES=5
cat > /tmp/run_eval.sh << EOF
#!/bin/bash
docker exec drone-bombard-harmonic bash -lc '
  source /opt/ros/humble/setup.bash
  source /root/ros2_ws/install/setup.bash
  source /workspace/ros2_ws/install/setup.bash
  cd /workspace/ros2_ws
  python3 -c "
from rl_navigation.drone_drop_env import DroneDropEnv
from stable_baselines3 import SAC
import numpy as np, time

env = DroneDropEnv(config_path=\"/workspace/ros2_ws/install/rl_navigation/share/rl_navigation/config/hyperparams.yaml\")
model = SAC.load(\"/workspace/ros2_ws/rl_checkpoints/sac_drop_final.zip\")

print(\"Environment ready. Open GUI now.\", flush=True)
time.sleep(30)

for ep in range($EPISODES):
    obs, _ = env.reset()
    done = False
    total_reward = 0
    steps = 0
    while not done:
        action, _ = model.predict(obs, deterministic=True)
        obs, reward, term, trunc, info = env.step(action)
        total_reward += reward
        steps += 1
        done = term or trunc
    drop_err = info.get(\"drop_error_actual_m\", \"N/A\")
    trigger = info.get(\"drop_trigger\", \"N/A\")
    d_xy = info.get(\"d_xy\", \"N/A\")
    trunc_reason = info.get(\"truncate_reason\", \"\")
    print(f\"EP{ep+1}: steps={steps} trigger={trigger} drop_err={drop_err} d_xy={d_xy} reward={total_reward:.1f} {trunc_reason}\", flush=True)

print(\"Evaluation complete. Sim stays alive for inspection.\", flush=True)
time.sleep(3600)
env.close()
"
'
EOF
tmux new-session -d -s eval "bash /tmp/run_eval.sh"

--------------------------------------------------------------------------------
 Step 5. 결과 확인
--------------------------------------------------------------------------------

tmux에서 에피소드별 결과를 확인:

tmux capture-pane -t eval -p | tail -20

출력 예시:
  EP1: steps=202 trigger=random drop_err=10.6 d_xy=10.4 reward=103.6
  EP2: steps=275 trigger=random drop_err=10.1 d_xy=10.3 reward=171.6
  EP3: steps=500 trigger=N/A drop_err=N/A d_xy=10.7 reward=157.9 timeout
  EP4: steps=394 trigger=auto drop_err=5.3 d_xy=5.3 reward=270.0

확인 항목:
  - d_xy가 줄어들고 있는가 (타겟 접근 학습)
  - drop_error가 d_xy와 비슷한가 (실제 물리 drop 작동)
  - trigger=auto가 있는가 (타겟 근처 정밀 drop)
  - reward가 양수인가 (정상 학습)

================================================================================
 [C] 타겟 위치 변경 테스트 (향후 구현 예정)
================================================================================

현재 타겟 위치 (11, 10)은 yaml + world SDF에 고정.
학습도 이 위치에서만 진행 → 다른 위치에서는 일반화 안 될 수 있음.

향후 일반화 학습 후 검증 시:
  1. hyperparams.yaml의 target_enu_x, target_enu_y 변경
  2. world SDF의 x_marker pose 변경 (동일 좌표로)
  3. install 미러링
  4. [A]의 Step 1~6 동일하게 실행

또는 evaluate 스크립트에 --target-x --target-y 옵션 추가하여
yaml 수정 없이 테스트 가능하도록 개선 예정.

테스트 시나리오 (향후):
  - 타겟 위치 소폭 변경 (11,10) → (15,12): 미세 일반화
  - 타겟 위치 대폭 변경 (11,10) → (30,25): 원거리 일반화
  - 타겟 위치 반대 방향 (11,10) → (-10,-5): 방향 일반화
  - 드론 spawn 위치 변경: 다른 출발점에서도 작동하는지
