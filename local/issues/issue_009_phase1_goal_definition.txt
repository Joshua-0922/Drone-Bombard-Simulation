================================================================================
 Issue #009 — Phase 1 졸업 기준 재정립
================================================================================
생성일 : 2026-05-25
상태   : Round 1 후 결정


================================================================================
 1. 문제점
================================================================================

현재 Phase 1 졸업 기준 (design_review_2026-05-23.md §6-6):
  6개 중 5개 충족:
    1. total_drop_count ≥ 30
    2. mean_d_xy (final) ≤ 10m
    3. crash_rate < 0.1
    4. critic_loss < 500
    5. ent_coef < 0.5
    6. deterministic evaluate drops ≥ 2

문제:
  - total_drop_count는 신뢰할 수 없다
    auto_drop_threshold=10m이면 대충 근처만 가도 발동 → 양 ≠ 질
  - deterministic evaluate drops ≥ 2는 현재 달성 불가 (Issue #004)
  - 나머지(critic_loss, ent_coef)는 학습 안정성 지표지 성능 지표가 아님
  - "학습이 잘 되고 있는지"를 판단할 명확한 기준이 없음


================================================================================
 2. 현재 측정 가능한 metric
================================================================================

  이미 있는 것:
    - total_drop_terminated_count (누적 drop 수)
    - total_success_count (d_error ≤ 0.5m 누적)
    - total_jackpot_count (d_error ≤ 0.1m 누적)
    - mean_d_xy (평균 타겟 거리)
    - drop_error_actual_m (per-rollout 평균 오차)
    - 각종 truncate count

  없지만 추가 가능한 것:
    - 최근 N episode drop률 (sliding window)
    - drop_error 분포 (중앙값, p25, p75)
    - mean_drop_error 추세 (감소하고 있는가)
    - deterministic evaluate drop_error (per milestone)


================================================================================
 3. Phase 1 졸업 기준 후보
================================================================================

  방안 A: drop_error 기반
    "최근 100 episode의 평균 drop_error ≤ 5m"
    장점: 질을 직접 측정
    단점: 새 metric 추가 필요 (sliding window)

  방안 B: 단계적 threshold
    Phase 1a: "drop이 발생한다" (total_drop > 30)
    Phase 1b: "drop_error가 줄고 있다" (추세 감소)
    Phase 1c: "mean_drop_error ≤ 5m"
    장점: 중간 진행도 확인 가능
    단점: 각 단계 기준이 여전히 자의적

  방안 C: deterministic eval 기준으로 통일
    "deterministic evaluate 5 episode에서 mean_drop_error ≤ 5m"
    장점: 배포 기준과 동일, 가장 엄격하고 의미 있음
    단점: 현재 deterministic에서 drop 자체가 안 됨 (Issue #004 선결)

  방안 D: Phase 1 목표를 축소
    Phase 1 = "타겟에 안정적으로 접근"만 (drop 성공은 Phase 2 이후)
    졸업 기준: "mean_d_xy ≤ 5m, crash_rate < 0.05"
    장점: 현실적, 달성 가능, 기초 다지기
    단점: drop 학습이 Phase 2로 밀림


================================================================================
 4. 논의 필요 사항
================================================================================

  - Phase 1에서 "drop 정밀도"까지 요구할 것인가,
    아니면 "안정적 접근"까지만 하고 Phase 2에서 drop을 다룰 것인가
  - auto_drop_threshold와 졸업 기준의 관계
    (threshold=10m인데 졸업 기준이 5m이면 구조적 모순)
  - success_threshold (현재 0.5m) 완화 여부
    중간 목표로 3m이나 5m을 쓸 것인가


================================================================================
 5. 연관 안건
================================================================================

  Issue #001 — 보상 구조 (졸업 기준이 바뀌면 보상도 맞춰야)
  Issue #004 — deterministic eval drop 0 (방안 C의 선결 조건)
  Issue #006 — hybrid drop (Phase 전환 기준에 영향)
  Issue #008 — 구조적 가능성 (불가능한 목표를 세우면 안 됨)
