================================================================================
 1. 문제점
================================================================================

현재 drop 보상은 두 시점의 데이터를 따로 사용:
  - 분리 시점: d_impact(CCIP 예측)으로 "언제 drop할지" 결정
  - 착탄 시점: actual_error(실제 오차)로 "보상 얼마 줄지" 결정

두 데이터 사이의 관계를 에이전트가 학습할 방법이 없다.
결과(actual_error)만 보고 보상을 주면, 에이전트는 "왜 그 결과가 나왔는지"
(어떤 비행 조건에서 놓았기 때문인지) 학습하기 어렵다.


================================================================================
 2. 제안: 분리/착탄 이중 보상
================================================================================

보상을 세 요소로 분해:

  reward = release_quality(분리 시 상태)
         + impact_accuracy(실제 오차)
         + prediction_bonus(예측-실제 일치도)

  a) release_quality — "어떤 상태에서 놓았는가"
     분리 시점의 드론 자세, 속도, 고도 기반
     예: 안정된 자세 + 적절한 고도 + 저속 비행 → 높은 보상
     에이전트가 "좋은 release 조건"을 직접 학습

  b) impact_accuracy — "결과가 어땠는가" (현재 보상과 동일)
     actual_error 기반 precision reward
     예: w_drop_base * exp(-k2 * actual_error)

  c) prediction_bonus — "예측이 맞았는가"
     |d_impact - actual_error| 가 작을수록 보상
     에이전트가 "CCIP가 정확해지는 비행 조건"을 찾도록 유도
     → CCIP 오차 보정을 간접적으로 학습


================================================================================
 3. 에이전트가 배울 수 있는 것
================================================================================

  현재 (actual_error만):
    "결과적으로 가까우면 좋다" → 어쩌다 맞추기

  이중 보상 적용 시:
    "고속 비행에서 놓으면 CCIP 갭이 크다 → 저속이 유리"
    "고도가 높으면 낙하 시간이 길어 오차가 커진다 → 적정 고도 유지"
    "안정된 자세에서 놓으면 예측이 정확하다 → release 전 자세 안정화"
    → 어떤 조건에서 놓으면 정확한지 체계적으로 학습


================================================================================
 4. 구현 시 필요 데이터
================================================================================

  분리 시점 (이미 step()에서 접근 가능):
    pos     — 드론 위치
    vel     — 드론 속도
    ang     — 각속도
    roll, pitch — 자세
    d_impact — CCIP 예측값
    altitude — 고도

  착탄 시점 (이미 drop_calculator에서 제공):
    actual_error — 실제 오차 (drop_error_actual_m)

  추가 필요:
    분리 시점 데이터를 step()에서 캡처하여 보상 계산에 사용
    (현재도 pos, vel, ang 등은 step() 내에서 접근 가능 — 저장만 하면 됨)


================================================================================
 5. 주의사항
================================================================================

  - release_quality의 "좋은 조건"을 사전에 정의해야 함
    → 어떤 속도/고도/자세가 좋은지 물리적 근거 필요
    → 또는 학습 데이터에서 상관관계를 먼저 분석
  - prediction_bonus는 CCIP 모델 자체가 바뀌면 재조정 필요
  - 보상 항이 3개로 늘어남 → 스케일 균형 (Issue #003 연동)
