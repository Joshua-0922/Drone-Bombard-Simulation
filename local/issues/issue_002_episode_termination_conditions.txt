================================================================================
 1. 개요
================================================================================

드론이 물리적으로 위험하거나 학습에 무의미한 행동을 하면 해당 에피소드를
즉시 종료(truncate)하고 음수 보상을 부과하여 다음 에피소드로 넘어간다.

이 문서는 "어떤 조건에서 에피소드를 끊을 것인가"를 정의하고 관리한다.


================================================================================
 2. 현재 조기종료 조건 — 전체 목록
================================================================================

  우선순위: crash > overspeed > ang_vel > inverted > timeout

  ┌──────────────┬──────────────────────────┬──────────┬────────────┐
  │ 조건          │ 감지 기준                 │ 페널티    │ 상태        │
  ├──────────────┼──────────────────────────┼──────────┼────────────┤
  │ crash        │ altitude < 3.0m (step>1) │ -50      │ Round 1    │
  │              │ altitude < 0.5m (무조건)  │          │            │
  ├──────────────┼──────────────────────────┼──────────┼────────────┤
  │ overspeed    │ speed > 20.0 m/s         │ -30      │ 유지       │
  ├──────────────┼──────────────────────────┼──────────┼────────────┤
  │ ang_vel      │ ||omega|| > 2.0 rad/s    │ -30      │ 유지       │
  ├──────────────┼──────────────────────────┼──────────┼────────────┤
  │ inverted     │ |roll| or |pitch| > 60°  │ -30      │ 유지       │
  ├──────────────┼──────────────────────────┼──────────┼────────────┤
  │ timeout      │ step ≥ 500               │ -15      │ 스케일 조정 │
  │              │ (drop 미발동 시만)         │          │            │
  ├──────────────┼──────────────────────────┼──────────┼────────────┤
  │ out_of_range │ d_xy > 100m              │ -30      │ Round 1    │
  └──────────────┴──────────────────────────┴──────────┴────────────┘

 3. 개선 필요 항목
================================================================================


--------------------------------------------------------------------------------
 3-1. crash (최저 고도) — 개선 필요
--------------------------------------------------------------------------------

  현재:
    조건       altitude < 3.0m, step > 10 이후만
    penalty    -100
    yaml 키    min_altitude, min_altitude_start_step, penalty_crash

  문제:
    - GUI에서 드론이 지면(0m)에 닿은 뒤 바운스 관찰됨
    - grace period(첫 10 step) 동안 검사 미실시
    - RL step 간격(20ms) 사이에 3m → 0m → 바운스 → 3m+ 통과 가능

  개선안:
    a) min_altitude_start_step: 10 → 1
    b) 절대 ground contact 체크 추가:
       altitude < 0.5m → crash (step 무관, 무조건)


--------------------------------------------------------------------------------
 3-2. out_of_range (최대 거리) — 신규 필요
--------------------------------------------------------------------------------

  현재: 미구현. 드론이 타겟과 무관한 방향으로 무한히 날아가도 에피소드 지속.
        timeout(500 step)까지 기다려야 종료됨.

  문제:
    - 학습 초기에 드론이 타겟 반대 방향으로 비행하는 경우 빈번
    - 500 step 동안 무의미한 데이터만 replay buffer에 쌓임
    - 학습 시간 낭비

  개선안:
    새로운 truncate 조건 추가:
      if d_xy > max_distance:
          truncated = True
          truncate_reason = 'out_of_range'
          reward += penalty_out_of_range

    파라미터 (yaml 추가):
      max_distance         : 100.0   (타겟까지 2D 거리, m)
      penalty_out_of_range : -30     (#003 스케일 맞춤)

    근거:
      - CRUISE 시작 시 d_xy ≈ 50~60m (spawn 위치 기준)
      - 100m는 출발점의 약 2배 → 타겟 반대로 날아간 것이 확실
      - grace 불필요: CRUISE 시점에 이미 d_xy < 100m

    wandb 추적:
      env/total_truncate_out_of_range_count 추가

================================================================================
 5. 페널티 크기 및 부과 방식 논의
================================================================================

각 종료 조건의 페널티 크기를 어떻게 정해야 하는지, 그리고 페널티를
부과하는 방법에도 선택지가 있다.

--------------------------------------------------------------------------------
 5-1. 페널티 크기 — 기준점
--------------------------------------------------------------------------------

  Round 1 적용 후 보상 규모:
    drop_attempt_bonus   = 30
    per-step 보상 누적   ≈ -50 ~ +200 (500 step 기준)
    jackpot              = 50
    truncation (timeout) = -15

  페널티가 너무 작으면:
    → 위험 행동의 비용이 낮아 agent가 무시
    → 예: crash=-10 이었던 이전 설정에서 crash 빈발

  페널티가 너무 크면:
    → agent가 지나치게 보수적 → 타겟 접근 자체를 꺼림
    → critic 학습 불안정 (극단적 음수값이 value function 왜곡)

  기준: drop 보상(150 또는 50)의 1~2배 범위가 적절.
        "이 행동을 하면 drop 성공 1~2회분의 보상을 날린다"는 신호.

  현재 페널티 점검:
    crash    : -100  (drop 보상 대비 0.67배 또는 2.0배)  → 적절~강함
    overspeed: -50   (drop 보상 대비 0.33배 또는 1.0배)  → 적절
    ang_vel  : -50   → 적절
    inverted : -50   → 적절
    timeout  : -30   → Issue #001에서 별도 논의

--------------------------------------------------------------------------------
 5-2. 페널티 부과 방식 — 선택지
--------------------------------------------------------------------------------

  방식 A: 고정 페널티 (현재 방식)
    종료 시 한 번에 고정값 부과 (예: -100)
    장점: 단순, 예측 가능
    단점: "얼마나 심하게 위반했는지" 구분 불가

  방식 B: 비례 페널티
    위반 정도에 비례 (예: crash 시 penalty = -100 * (1 - altitude/min_alt))
    장점: "거의 위반" vs "완전히 바닥 충돌" 구분 가능
    단점: 복잡, 튜닝 어려움

  방식 C: 누적 경고 → 종료
    임계값 근처에서 per-step 경고 페널티, 초과 시 종료
    예: altitude 3~5m → per-step -5, altitude < 3m → -100 + 종료
    장점: agent가 "위험 구간"을 학습할 수 있음
    단점: 학습 초기에 경고 구간에서 머무르는 전략 가능

  현재 권장: 방식 A (고정 페널티) 유지.
  학습이 안정화되면 방식 C 검토 가능.

 6. 적용 시 주의사항
================================================================================

  - 조기종료 조건 추가/변경 → Fresh Start 권장 (replay buffer 오염 방지)
  - 5k dry-run 후 각 truncate_reason 비율 확인:
    - crash 급증 → 임계값 너무 빡빡
    - out_of_range 과다 (>50%) → 임계값 너무 낮거나 spawn 위치 문제
  - Issue #001(drop 보상 구조)과 동시 적용 가능
