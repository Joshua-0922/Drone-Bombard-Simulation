================================================================================
 Issue #006 — Auto + Manual Drop 하이브리드 방식
================================================================================
생성일 : 2026-05-25
상태   : 적용 예정 (Round 1)
관련   : Issue #001, #004


================================================================================
 1. 배경
================================================================================

현재 Phase 1은 auto_drop만 사용 (action[4] 비활성).
d_impact ≤ threshold 도달 시 자동 drop — 에이전트가 타이밍 제어 불가.
이로 인해:
  - d_impact이 처음 threshold 이하가 되는 순간에 강제 drop
  - 더 가까이 갈 수 있어도 못 감
  - 정밀 drop 학습이 구조적으로 어려움

"첫 진입 즉시 발동" 문제 예시:
  step 100: d_impact = 15m  → drop 안 됨
  step 110: d_impact = 11m  → drop 안 됨
  step 115: d_impact = 9.8m → 자동 drop 발동 ← 여기서 끝
  step 120: d_impact = 5m   → 도달 못함
  step 130: d_impact = 0.3m → 도달 못함

에이전트가 아무리 완벽한 궤적을 학습해도, d_impact이 점진적으로
줄어드는 접근 경로라면 threshold 지점에서 무조건 끊긴다.
정밀 drop이 가능하려면 d_impact이 처음 threshold를 넘는 순간에
이미 0에 가까워야 하는데, 이는 매우 특수한 fly-by 궤적만 가능.


================================================================================
 2. 제안: 하이브리드 방식
================================================================================

auto_drop과 manual_drop을 동시 활성화:

  manual_drop = float(action[4]) > 0.5
  if (manual_drop or d_impact <= threshold) and not self.dropped:
      drop 발동

  auto_drop = 안전망 (threshold 이하에서 자동 발동)
  manual_drop = 에이전트 선택 (원할 때 직접 발동)

학습 단계별 예상 동작:
  초기: 에이전트가 타이밍 모름 → auto_drop이 처리 (기존과 동일)
  중기: "auto_drop 전에 내가 먼저 떨어뜨리면 보상이 더 높다" 발견
  후기: 최적 타이밍에 직접 drop, auto_drop은 보험으로만 존재


================================================================================
 3. auto_drop threshold 연동
================================================================================

하이브리드 방식과 threshold 축소를 함께 적용하면 효과 극대화:

  threshold 10m (현재): auto_drop이 너무 일찍 발동 → manual 의미 없음
  threshold 2m:  에이전트가 "2m까지 기다리기 vs 지금 내가 drop" 비교 학습
  threshold 0.5m: 사실상 manual_drop 위주, auto_drop은 극단적 보험만

threshold를 줄일수록 manual_drop의 역할이 커짐.


================================================================================
 4. 구현
================================================================================

drone_drop_env.py step() 내 1줄 주석 해제 + 조건문 수정.
action space 변경 없음 (이미 5차원, action[4] 존재).
checkpoint 호환성 유지 (action space shape 동일).

단, 보상 구조 변경(Issue #001)과 동시 적용 시 Fresh Start 권장.


================================================================================
 5. 위험
================================================================================

  - 학습 초기에 action[4]를 랜덤 탐색 → 의미 없는 drop 남발 가능
    → learning_starts 기간에는 auto_drop만 활성화하는 방법도 고려
  - action[4] > 0 의 threshold가 모호
    → 0.5 이상만 drop으로 인정하는 등 조정 가능
