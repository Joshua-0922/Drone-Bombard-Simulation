================================================================================
 1. 문제점
================================================================================

연속 에피소드의 행동 양상이 크게 다르다. 한 에피소드에서는 타겟 접근,
다음 에피소드에서는 전혀 다른 방향으로 비행. 정책이 안정되지 않고 왔다갔다.

원인: 보상 절대값이 크고, 터미널/per-step 보상 간 격차가 커서
critic의 value estimate가 흔들림.


================================================================================
 2. 현재 보상 규모
================================================================================

  터미널 보상:
    drop_attempt_bonus   = +150
    r_success_jackpot    = +100
    penalty_crash        = -100
    penalty_overspeed    = -50
    penalty_bad_attitude = -50
    truncation_penalty   = -30

  per-step 보상 (매 step 누적):
    w_dist               = 0.5  (거리 변화)
    w_heading            = 0.7  (방향 정렬)
    w_time               = -0.05 (시간 페널티)
    w_ang_vel            = -0.05 * ||omega||²
    w_action_smooth      = -0.05 * ||Δa||²
    w_impact             = 0.4 * exp(-0.05 * d_impact)

  에피소드 총 보상 범위:
    drop 성공:  +150 ~ +250
    crash:      -100 ~ -150
    timeout:    -50 ~ +30
    per-step 누적: ±30 (500 step 기준)

  터미널(±150) vs per-step 누적(±30) → 5배 차이.
  에피소드 결말에 따라 총 보상이 -150 ~ +250, 편차 400.


================================================================================
 3. 심층 분석 — 왜 타겟 방향으로도 안 가는가
================================================================================

per-step 접근 보상은 이론상 충분히 강하다:
  w_heading = 0.7 × 500 step = +350 (타겟 방향 유지 시)
  w_dist    = 0.5 × 50m 접근 = +25
  합계 ≈ +375 (drop bonus 150보다 큼)

그런데 같은 "타겟 접근" 행동의 결말이 매번 다르다:
  에피소드 A: 타겟 접근 → drop → +250
  에피소드 B: 타겟 접근 → crash → -100
  에피소드 C: 타겟 접근 → timeout → -30
  에피소드 D: 랜덤 비행 → timeout → -40

critic(value function)은 "타겟으로 가면 미래 보상이 높다"를 추정해야
policy가 그 방향으로 수렴한다. 그런데 같은 행동의 결과가 -100 ~ +250
범위로 변동하면, critic이 "타겟 접근 = 좋다"를 확신하지 못한다.

결과적으로:
  - per-step 접근 신호(+375)는 이론상 강하지만
  - 터미널 보상 분산(±400)이 이를 덮어버려
  - critic이 per-step 신호를 제대로 학습하지 못하고
  - policy가 일관되게 타겟을 향하지 못함

이것이 "드론이 이상한 방향으로 날아가는" 근본 원인.


================================================================================
 4. 해결 방안 후보
================================================================================

  방안 A: 전체 스케일 축소
    모든 보상을 1/N로 나눔 (예: N=3 또는 N=5)
    비율 유지, 절대값만 축소
    SAC auto entropy tuning이 적응
    critic 학습 안정화 기대

  방안 B: 터미널 보상만 축소
    터미널 보상을 per-step 누적과 비슷한 규모로
    "과정"의 비중이 높아짐 → 비행 경로 학습 강화
    drop 보상이 약해지면 drop 동기 감소 위험 (Issue #001 연관)

  방안 C: per-step 보상 강화
    per-step 보상의 가중치를 올려 터미널과 비율 맞춤
    비행 과정의 학습 신호 강화
    단, step 수가 많아지면 누적이 터미널을 압도할 수 있음
